# Content Hub Site Skill

Build SEO-ready content hub websites where **brand**, **content**, and **SEO metadata** are fully decoupled from components. Change one config file → launch a new site.

## Architecture Principle

```
src/lib/site-config.ts    ← Brand identity (name, colors, logo, tagline, nav, footer)
src/lib/page-content.ts   ← All page text content (headings, paragraphs, cards, lists)
src/lib/seo-config.ts     ← Per-route SEO metadata (title, description, JSON-LD)
src/components/            ← Reusable, data-driven components (never hardcode text)
src/pages/                 ← Page shells that compose components with content data
scripts/prerender.mjs      ← Build-time static HTML generation for SEO
```

Components import from config/content files. **Zero hardcoded strings in components or pages.**

---

## Phase Overview

| Phase | What Claude Does | Output |
|-------|-----------------|--------|
| **1 SITE CONFIG** | Define brand identity + site structure | `site-config.ts` + `project.json` |
| **2 CONTENT** | Write all page content as data objects | `page-content.ts` |
| **3 COMPONENTS & PAGES** | Build data-driven components + page shells | `src/components/`, `src/pages/` |
| **4 SEO** | Per-route metadata + prerender script | `seo-config.ts` + `scripts/prerender.mjs` |
| **5 LAUNCH** | Build verification + checklist | Production build + sitemap |

---

## ⚠️ MANDATORY: React SPA Prerender Architecture

Same rules as the `local-biz-website` skill. Non-negotiable:

1. **NEVER use `useEffect`, `document.title`, or client-side DOM manipulation for SEO tags.**
2. **SEO data = pure data objects** in `src/lib/seo-config.ts`.
3. **Build-time prerender** via `scripts/prerender.mjs` generates static HTML per route.
4. **Build pipeline**: `"build": "vite build && node scripts/prerender.mjs"` in package.json.
5. **Sitemap + robots.txt** generated by prerender script, not manually maintained.
6. **All `.md` files must be gitignored** — add `*.md` to `.gitignore`.

## PHASE 1 — SITE CONFIG

### Process
1. Gather from user: site topic/niche, brand name, tagline, target audience, desired pages
2. Define color palette (primary + accent HSL values for Tailwind CSS variables)
3. Define navigation structure and footer layout
4. Output `project.json` + `src/lib/site-config.ts`

### `project.json` Structure
```json
{
  "site": {
    "name": "Jarvis AI",
    "tagline": "The enterprise AI knowledge hub",
    "domain": "",
    "logo_text": "J",
    "target_audience": "Enterprise AI teams",
    "niche": "Enterprise AI education"
  },
  "pages": [
    { "slug": "/", "label": "Home", "in_nav": false },
    { "slug": "/ai-agents", "label": "AI Agents", "in_nav": true },
    { "slug": "/resources", "label": "Resources", "in_nav": true }
  ],
  "design": {
    "primary_hsl": "230 80% 56%",
    "accent_hsl": "260 60% 58%",
    "font": "Inter",
    "style": "clean, professional, enterprise"
  }
}
```

### `src/lib/site-config.ts` — Brand Identity

This file is the **single source of truth** for all brand-level data. See `references/site-config-template.ts`.

Key exports:
- `SITE` — name, tagline, logo, domain
- `NAV_ITEMS` — top navigation links
- `FOOTER_LINKS` — footer link groups
- `CTA_DEFAULTS` — default CTA text and links

**Rule**: Every component that shows the brand name, tagline, or navigation MUST import from this file. Never hardcode brand strings.

## PHASE 2 — CONTENT

### Process
1. For each page defined in `project.json`, write content as TypeScript data objects
2. All text goes in `src/lib/page-content.ts` — headings, paragraphs, card arrays, list items
3. Content is organized by page slug as keys
4. User can review and edit the single content file to update all pages

### `src/lib/page-content.ts` — Page Content

See `references/page-content-template.ts` for full structure.

Key patterns:
```typescript
// Each page exports a typed content object
export const homeContent = {
  hero: {
    badge: "Enterprise AI Knowledge Hub",
    headline: "Enterprise AI",
    headlineAccent: "Knowledge Hub",  // gradient text portion
    subtitle: "Learn how to build, deploy, and govern AI agents...",
    cta: { text: "Explore how enterprises implement AI", href: "/mcp-integrations" },
  },
  topics: [
    { title: "AI Agents", description: "...", href: "/ai-agents", articles: 12 },
  ],
  popularTopics: [...],
  useCases: [...],
}

export const articlePages: Record<string, ArticlePageContent> = {
  "/ai-agents": {
    badge: "AI Agents",
    headline: "AI Agents:",
    headlineAccent: "Autonomous Intelligence for Enterprise",
    subtitle: "Understanding how autonomous AI agents...",
    keyInsights: ["...", "..."],
    toc: [{ id: "section-id", label: "Section Title" }],
    sections: [
      { id: "section-id", heading: "What are AI Agents?", paragraphs: ["...", "..."] },
      { id: "types", heading: "Types of AI Agents", cards: [...] },
    ],
    diagrams: [{ title: "Agent Architecture", steps: ["Perception", "Memory", ...] }],
    relatedTopics: [...],
  },
}
```

### Content Types
- **Home page**: hero, topic cards, popular topics, use case preview, CTA
- **Article pages**: hero, key insights, TOC, content sections (paragraphs, cards, diagrams), related topics, CTA
- **Catalog pages** (Use Cases, Comparisons, Resources): hero, card grid, CTA
- **404 page**: heading, message, back link

**Rule**: Components receive content via props or imports. No inline text in JSX.

## PHASE 3 — COMPONENTS & PAGES

### Process
1. Build shared layout components first (SiteLayout, SiteHeader, SiteFooter)
2. Build reusable content components (TopicCard, KeyInsights, TableOfContents, DiagramBlock, RelatedTopics, CTABanner)
3. Build page shells that compose components with content data
4. All components are data-driven — they accept props, never contain hardcoded text

### Component Architecture

**Layout layer** (imports from `site-config.ts`):
| Component | Data Source |
|-----------|------------|
| `SiteHeader` | `SITE.name`, `SITE.logo_text`, `NAV_ITEMS` |
| `SiteFooter` | `SITE.name`, `SITE.tagline`, `FOOTER_LINKS` |
| `SiteLayout` | Composes Header + Footer around children |

**Content components** (receive props from page content):
| Component | Props |
|-----------|-------|
| `TopicCard` | `title`, `description`, `href`, `icon`, `articles` |
| `KeyInsights` | `insights: string[]` |
| `TableOfContents` | `items: { id, label }[]` |
| `DiagramBlock` | `title`, `steps: string[]` |
| `RelatedTopics` | `topics: { title, href, description }[]` |
| `CTABanner` | `title?`, `description?`, `linkText?`, `linkHref?`, `variant?` |

**Page shells** (import content, pass to components):
```typescript
// Example: ArticlePage pattern
import { articlePages } from "@/lib/page-content";
import { CTA_DEFAULTS } from "@/lib/site-config";

const AIAgents = () => {
  const content = articlePages["/ai-agents"];
  return (
    <SiteLayout>
      <ArticleHero {...content} />
      <ArticleBody content={content} />
      <CTABanner {...CTA_DEFAULTS} />
      <RelatedTopics topics={content.relatedTopics} />
    </SiteLayout>
  );
};
```

### Design Tokens
All colors use HSL CSS custom properties in `src/index.css`. To rebrand:
1. Change HSL values in `index.css` `:root` block
2. Change font import URL
3. Update `site-config.ts` brand fields

Custom utility classes to maintain:
- `gradient-text` — primary→accent gradient on text
- `gradient-bg` — primary→accent gradient background
- `gradient-subtle` — low-opacity gradient background
- `gradient-hero` — page hero background gradient
- `shadow-card` / `shadow-card-hover` — card elevation

## PHASE 4 — SEO

### Process
1. Create `src/lib/seo-config.ts` with per-route metadata
2. Create `scripts/prerender.mjs` for build-time HTML generation
3. Update `package.json` build script
4. Verify build output

### `src/lib/seo-config.ts`

See `references/seo-config-template.ts`. Key structure:

```typescript
import { SITE } from "./site-config";

export const routeSEO: Record<string, SEOData> = {
  "/": {
    title: `${SITE.name} | ${SITE.tagline}`,
    description: "...",
    jsonLd: buildWebSiteSchema(),
  },
  "/ai-agents": {
    title: `AI Agents: Autonomous Intelligence | ${SITE.name}`,
    description: "...",
    jsonLd: buildArticleSchema("AI Agents", "/ai-agents"),
  },
};
```

### JSON-LD Schema Types
- **Home**: `WebSite` + `Organization`
- **Article pages**: `Article` + `BreadcrumbList`
- **Catalog pages**: `CollectionPage` + `BreadcrumbList`
- **All pages**: Include `publisher` with `SITE.name`

### `scripts/prerender.mjs`

See `references/prerender-script.mjs`. Adapted from `local-biz-website` skill:
- Reads `dist/index.html` as template
- For each route: injects correct `<title>`, `<meta description>`, canonical URL, OG tags, JSON-LD
- Generates `sitemap.xml` and `robots.txt`
- Environment variable `SITE_DOMAIN` for production URL

## PHASE 5 — LAUNCH

### Pre-Launch Checklist
1. `npm run build` completes without errors
2. Grep `dist/` for page-specific `<title>` tags — confirm prerender worked
3. Verify `dist/sitemap.xml` contains all routes
4. Verify `dist/robots.txt` exists with correct sitemap URL
5. Test all internal links work (no dead `#` hrefs in production)
6. Lighthouse audit: target 90+ on Performance, SEO, Accessibility
7. Verify OG tags with social media preview tools

### Post-Launch
1. Submit sitemap to Google Search Console
2. Set up Google Analytics / tag manager
3. Monitor Core Web Vitals in Search Console

## Multi-Site Launch Workflow

To launch a new site from the same codebase:

### Option A — Fork & Rebrand (recommended for divergent sites)
1. Clone the repo
2. Edit `src/lib/site-config.ts` — change name, tagline, logo, nav, footer
3. Edit `src/lib/page-content.ts` — rewrite all content for new niche
4. Edit `src/lib/seo-config.ts` — update all titles/descriptions/keywords
5. Edit `src/index.css` — change primary/accent HSL values and font
6. Update `scripts/prerender.mjs` SITE_DATA and routes
7. Build and deploy

### Option B — Config-Driven Multi-Tenant (for similar sites)
1. Create `sites/site-a.json`, `sites/site-b.json` with brand + content data
2. Build script reads `SITE_ID` env var to select config
3. Single codebase, multiple builds
4. More complex but zero code duplication

### What to Change Per Site (Checklist)
| File | What to Change |
|------|---------------|
| `src/lib/site-config.ts` | Brand name, tagline, logo, nav items, footer links, CTA defaults |
| `src/lib/page-content.ts` | All page text content — headings, paragraphs, cards, lists |
| `src/lib/seo-config.ts` | Page titles, meta descriptions, JSON-LD data |
| `src/index.css` | HSL color values in `:root`, font import URL |
| `scripts/prerender.mjs` | SITE_DATA block, route definitions |
| `index.html` | Default `<title>`, `<meta description>`, favicon |
| `public/favicon.ico` | Site favicon |
| `project.json` | Site metadata for reference |

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Framework | React 18 + TypeScript |
| Build | Vite (SWC plugin) |
| Styling | Tailwind CSS 3 + CSS custom properties (HSL tokens) |
| UI | shadcn/ui (Radix UI, default style, CSS variables) |
| Routing | react-router-dom v6 |
| State | @tanstack/react-query |
| Icons | lucide-react |
| SEO | Build-time prerender (Node.js script) |
| Path alias | `@/` → `./src/` |
